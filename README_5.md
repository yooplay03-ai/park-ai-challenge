# 국립공원 위성 모니터링 AI 챌린지 — 불법 시설물(증축·벌목) 변화 탐지

2026 국립공원 위성 모니터링 AI 챌린지(주최: 국립공원공단, 주관·운영: 인공지능팩토리) 주제3 "불법 시설물 변화 탐지" 참가 프로젝트입니다.

동일 위치를 다른 시점에 촬영한 위성영상 pre/post 쌍(256×256)을 비교해 **신축·증축(new_building)** 과 **벌목(tree_removal)** 두 종류의 변화 영역을 폴리곤으로 탐지하는 bi-temporal change detection 문제를 다룹니다.

## 결과 요약

| 단계 | 설명 | Public 점수 |
|---|---|---|
| 베이스라인 | 대회 제공 원본 가중치 | 0.2745 |
| 1차 개선 | 합성 하드네거티브 데이터로 파인튜닝 | 0.2827 |
| 2차 개선 | + AI Hub 실데이터(Skyset) 혼합 파인튜닝 | 0.2830 |
| **3차 개선** | **+ 추론 신뢰도 임계값(CONF_THRESH) 0.8 → 0.5** | **0.2931 (68팀 중 46위)** |

가장 큰 개선은 재학습이 아니라 **추론 후처리 파라미터 하나를 조정한 것**에서 나왔습니다(자세한 내용은 아래 "무엇이 실제로 효과가 있었나" 참고). 대회 코드 제출 마감은 2026-10-06입니다.

## 문제 정의

- 입력: pre/post 위성 RGB 패치 쌍 (256×256, 지상 해상도 0.55~0.7m/px)
- 출력: `id,new_building,tree_removal` 형식 CSV. 각 셀은 변화 영역 폴리곤 목록의 JSON 문자열
- 평가: `0.5 × F1(변화 유무 판정) + 0.5 × 형상점수(경계 1px 허용 IoU 계열)`를 두 클래스에 대해 계산 후 평균
- 대회 자체는 학습/평가용 위성영상을 전혀 제공하지 않으며, 참가자는 baseline 가중치(UNet-ResNet18, 6채널 조기융합, 3클래스 출력)만 받습니다.

## 접근 방법

이 대회의 가장 큰 제약은 **학습 데이터가 없다**는 점이었습니다. 이를 해결하기 위해 세 방향으로 접근했습니다.

### 1. 무데이터 개선 (Test-Time Augmentation + 후처리 보정)

- **TTA**: 좌우반전/상하반전/180도회전 4-뷰의 softmax 확률을 평균해 예측 안정성 향상
- **신뢰도 임계값(CONF_THRESH) 튜닝**: 두 클래스 확률이 임계값 미만이면 배경으로 되돌려 오탐 억제. 평가 산식이 오탐(false positive)에 큰 페널티를 주는 구조라는 점에 착안해 시도했고, 실제로 프로젝트 전체에서 가장 효과적인 레버였음이 확인됨 (0.8 → 0.5, +0.0101)

### 2. 합성(synthetic) 데이터로 강건성 학습

실제 위성영상 없이, 절차적으로 생성한 pre/post 쌍으로 "변화가 아닌 차이"에 반응하지 않도록 하드 네거티브를 만들어 파인튜닝했습니다 (`train_finetune.py`).

- 계절/촬영조건에 따른 밝기·대비·감마·색조 차이 (`photometric_jitter`)
- 그림자 방향/길이 차이 (`add_shadow_band`)
- 시차(parallax)로 인한 수 화소 어긋남 (`small_parallax_warp`)
- 이동체(차량 등)로 인한 국소 색번짐 (`moving_vehicle_blob`)
- 위 왜곡을 모두 준 채 정답은 "무변화"로 두고, 인코더는 동결한 채 디코더 위주로 저학습률(3e-5) 미세조정 → 파국적 망각 방지

### 3. AI Hub 실데이터 반영

주최측이 학습 활용을 공식 허용한 [AI Hub "AI기반 국립공원 변화탐지 모니터링 플랫폼 구축"](https://aihub.or.kr) 데이터셋(dataSetSn=71363, Skyset 플랫폼 약 0.5m 해상도 — 대회 평가 해상도와 가장 근접)에서 동일 타일의 서로 다른 촬영 시점 LABEL 라스터 쌍을 비교해 실제 변화 마스크를 계산하고, 1024×1024 타일을 256×256 패치 16개로 분할해 학습용 pre/post/mask 데이터셋을 직접 구축했습니다.

- 라벨 픽셀값이 곧 분류 코드(10=건물, 60=산림 등)인 사전 래스터화된 데이터라 좌표 변환 없이 바로 사용 가능
- `new_building = (post==건물) & (pre!=건물)`, `tree_removal = (pre==산림) & (post!=산림)` 로 변화 마스크 계산
- 확보한 실데이터를 합성 데이터와 확률적으로 혼합(`MixedChangeDataset`)해 파인튜닝

## 무엇이 실제로 효과가 있었나

| 시도 | 비용 | Public 점수 개선 |
|---|---|---|
| 합성 하드네거티브 파인튜닝 | 중간 (스크립트 작성 + GPU 학습) | +0.0082 (0.2745→0.2827) |
| AI Hub 실데이터 혼합 파인튜닝 | 높음 (데이터 확보·가공·재학습) | +0.0003 (0.2827→0.2830, 오차범위 수준) |
| **CONF_THRESH 0.8→0.5** | **거의 없음 (설정값 1개 변경)** | **+0.0101 (0.2830→0.2931)** |

가장 비용이 큰 실데이터 확보·재학습이 가장 효과가 작았고, 가장 비용이 적은 후처리 파라미터 조정이 가장 큰 개선을 만들었습니다. 이는 이 대회의 평가 산식(F1이 오탐에 큰 페널티를 부여)에서, 모델을 더 정교하게 만드는 것보다 **이미 학습된 모델의 출력을 얼마나 보수적으로/정밀하게 후처리하느냐**가 실질적으로 더 중요한 변수였다는 것을 보여줍니다.

## 트러블슈팅 (겪었던 문제와 해결)

- **AI Hub 해외 IP 다운로드 차단**: Google Colab(해외 서버)에서 직접 다운로드 불가 → 국내 IP인 로컬 PC에서 다운로드 후 Google Drive 경유로 Colab에 전달
- **AI Hub 데이터 대용량(원본 이미지 42.91GB)**: Google Drive 무료 15GB 한도 초과로 업로드 실패 → LABEL 라스터만으로 사전 분석해 확보 가능한 학습 예제 수를 먼저 추정한 뒤, 비용 대비 효과를 판단해 진행 여부 결정
- **AIFactory 제출 노트북 버그**: `%aifactory submit`이 채점 서버에서 노트북 전체를 처음부터 재실행하며, 제출 셀 뒤에 남은 셀도 함께 실행됨 → 로컬 테스트용 코드(`google.colab` import 등)를 `try/except`로 감싸고, 제출 셀을 노트북의 마지막 셀로 고정
- **Colab 무료 런타임의 잦은 연결 끊김**: 학습 도중 진행 상황 유실 → N스텝마다 체크포인트를 Google Drive에 중간 저장하도록 학습 스크립트 수정
- **Google Drive 마운트 zip의 느린 랜덤 접근**: 학습용 실데이터 zip을 Drive에 둔 채 직접 읽으면 파일당 접근 지연이 커 병목 → 로컬 디스크로 복사 후 사용

## 기술 스택

- **모델**: UNet (ResNet18 인코더, ImageNet 사전학습 없이 대회 baseline 가중치 사용), PyTorch, `segmentation_models_pytorch`
- **입력**: pre/post RGB를 채널 축으로 이어붙인 6채널 조기융합(early fusion), 출력은 배경/신축/벌목 3클래스
- **후처리**: 픽셀 마스크 → 행 단위 run-length 사각형 → `shapely` 합집합·단순화로 폴리곤 변환
- **학습 환경**: Google Colab (GPU), Google Drive
- **데이터**: AI Hub 공개 데이터셋(위성/항공 변화탐지), 절차적 합성 데이터 생성

## 폴더 구조 / 파일 설명

```
.
├── README.md              # 이 파일
├── predict.ipynb           # 제출용 추론 노트북 (TTA + CONF_THRESH 오탐억제 포함)
├── train_finetune.py       # 합성 데이터 + AI Hub 실데이터 혼합 파인튜닝 스크립트
└── requirements.txt         # 의존성 목록
```

체크포인트 파일(`assets/model/*.pt`)은 용량 문제로 이 저장소에는 포함하지 않았습니다.

## 실행 방법

```bash
pip install -r requirements.txt

# 추론 (로컬 테스트, pairs.csv + images/<id>/{pre,post}.png 형식의 입력 폴더 필요)
AIF_INPUT_DIR=<입력 폴더> AIF_PREDICTION_PATH=./prediction.csv \
  jupyter nbconvert --to notebook --execute predict.ipynb

# 파인튜닝 (합성 데이터만 사용)
python train_finetune.py --ckpt-in <원본 체크포인트> --ckpt-out <출력 경로> --steps 1500

# 파인튜닝 (AI Hub 실데이터 혼합)
python train_finetune.py --ckpt-in <원본 체크포인트> --ckpt-out <출력 경로> \
  --aihub-zip <AI Hub 패치 zip 경로> --steps 3000 --real-data-ratio 0.5
```

이 프로젝트는 "학습 데이터가 전혀 제공되지 않는 대회"라는 제약에서 출발해, 데이터 없이 할 수 있는 것(TTA, 합성 하드네거티브, 후처리 튜닝)과 외부 데이터를 확보해서 하는 것(AI Hub 실데이터 반영) 두 방향을 모두 실험해 본 과정입니다. 결과적으로는 정교한 재학습보다 평가 산식을 이해하고 그에 맞춰 추론 후처리를 조정하는 쪽이 훨씬 효율적인 개선 경로였다는 것이 이번 프로젝트의 가장 큰 교훈이었습니다.
